# 단위소프트 백엔드

이 폴더는 별도로 Git으로 관리할 수 있는 백엔드 소스 사본입니다. PostgreSQL 데이터, API, 관리자 인증, 콘텐츠 발행, 수집·작성 작업자를 담당합니다. 현재 홈페이지와 관리자는 기존 서버 렌더링(SSR)을 유지합니다. 화면 HTML은 이 서버가 생성하고 CSS·브라우저 JavaScript·폰트·이미지는 옆의 danwisoft-frontend 저장소가 제공합니다.

프런트엔드 서버는 정적 자산을 제공하고 나머지 요청을 이 서버로 서명하여 전달합니다. 사용자는 프런트엔드 주소로 접속합니다. 두 저장소가 같은 브라우저 주소를 사용하므로 쿠키, 관리자 이벤트 스트림, 폼과 기존 보안 정책을 함께 유지합니다. 백엔드 직접 운영 요청은 기존 HMAC 검증과 nonce 재전송 검사를 통과해야 합니다.

## 파일과 작업 위치

- src/: Node 서버, API, DB 처리, SSR 화면 구성, 인증, 작업자.
- templates/home.html: 기존 홈 화면 중 서버가 사용하는 HTML 템플릿. 수정 뒤 빌드하면 반영됩니다.
- scripts/: 빌드, 마이그레이션, 시드, 테스트 보조 도구.
- db/: 순서가 유지되는 PostgreSQL 마이그레이션.
- tests/: 기존 기능 검증. 일부 보고서는 tests/results/에 생성됩니다.
- editorial/: 기존 작성·운영 정책 문서. 문서에서 언급하는 Sites gateway는 이번 분리본의 프런트엔드 gateway에 해당합니다.
- backend/와 src/generated.ts: 생성 결과이며 Git 관리에서 제외됩니다.

원본 사이트, 운영 환경변수, 기존 DB, 업로드, 실행 기록은 포함하지 않았습니다. 이 사본에는 GitHub 원격 저장소 주소도 설정되어 있지 않습니다.

## 설치와 실행

Node.js 24.15 이상, 25 미만이 필요합니다. 이 폴더에서 아래 명령을 실행합니다.

    npm ci
    npm run build
    npm run check

.env.example을 .env로 복사하고 사용할 환경의 값을 직접 준비합니다. 실제 값은 Git에 넣지 않습니다. 명령은 .env가 있으면 읽으며, 호스팅 환경에서 제공하는 환경변수도 사용할 수 있습니다.

    npm start
    npm run worker

기본 백엔드 PORT는 5196입니다. 일반적인 로컬 분리 개발은 프런트엔드의 로컬 안내에 따라 프런트엔드 프록시와 이 서버를 함께 실행합니다. DEV_DATABASE는 PGlite 검수용으로만 사용하고 운영에서는 false로 둡니다. LOCAL_POSTGRES는 기존 localhost 전용 PostgreSQL 접속 방식을 위한 옵션이며 운영 서버에서는 false로 둡니다.

이 저장소에는 정적 public 폴더가 없습니다. 공개 CSS·JavaScript·이미지 확인은 프런트엔드 주소에서 진행합니다.

## DB와 운영자

이 내보내기는 새 DB와 익명 초기 데이터를 기준으로 준비했습니다. 소스의 과거 고객 식별자를 익명화했으므로 기존 실제 DB를 바로 연결하지 마세요. 기존 콘텐츠·사례 ID·관계·미디어는 별도 비공개 이전 검수와 필요한 데이터 변환 후 연결합니다. PRIVATE_SITE=true는 검색 노출 설정이며 접근 차단 기능이 아닙니다.

DATABASE_URL에는 실행용 PostgreSQL 계정이 필요합니다. 운영 계정은 필요한 테이블 데이터 권한만 부여하고, 스키마 변경 권한은 분리합니다. 마이그레이션 실행 시에는 마이그레이션 권한을 가진 연결 주소를 DATABASE_URL로 주입하여 실행한 뒤 실행용 주소로 되돌립니다.

    npm run migrate
    npm run seed

마이그레이션과 시드는 기존 구조·레코드를 유지하는 기존 로직을 사용합니다. 기존 실제 DB 연결이나 데이터 복사는 이번 사본 생성에 포함되지 않습니다. 데이터베이스 주소와 권한은 배포 환경에서 별도로 준비해야 합니다.

OWNER_EMAIL은 기존 운영자 권한 판정에 사용됩니다. 실제 운영자 계정과 ADMIN_USER_ID는 기존 활성 운영자 레코드에 맞춰 준비합니다. 새 관리자 계정·권한을 자동 등록하는 절차는 이 사본에 추가하지 않았습니다.

운영 관리자 로그인은 ADMIN_LOGIN_ID, ADMIN_PASSWORD_HASH, ADMIN_SESSION_SECRET, ADMIN_USER_ID를 서버 환경변수로 준비합니다. 비밀번호는 기존 코드의 해시 형식으로 설정하고 평문 비밀번호를 저장하지 않습니다. 해시 생성 규칙은 src/admin-auth.ts의 passwordHash를 기준으로 확인할 수 있습니다.

선택적인 /admin/setup-login 설정 화면은 LOCAL_POSTGRES=true, localhost DB·SITE_URL, LOCAL_AUTH_SECRET, 기존 local-owner와 OWNER_EMAIL 조건을 충족한 이 PC에서만 동작합니다. PostgreSQL 설치 계정 확인도 기존 방식으로 수행합니다. 이 기능을 사용할 때 LOCAL_ENV_FILE에 보호된 환경변수 파일 경로를 지정할 수 있고, 생략하면 이 저장소의 .env를 사용합니다. 이 경로는 서버 설정이며 브라우저 입력으로 받지 않습니다. 호스트 제한과 운영자 확인 조건은 유지했습니다.

## 프런트엔드 연결

SITE_URL은 브라우저에서 접속할 프런트엔드 주소입니다. 운영에서는 HTTPS 주소를 사용합니다. GATEWAY_SECRET은 프런트엔드 서버의 값과 반드시 같아야 합니다. BACKEND_URL은 프런트엔드 저장소에서만 설정합니다.

빌드는 홈 템플릿만 src/generated.ts로 준비한 뒤 Node 실행 파일을 생성합니다. 프런트엔드 파일이나 Sites 배포 메타데이터를 읽지 않으므로 이 폴더를 단독으로 복제하여 빌드할 수 있습니다. 서버 렌더링 HTML 구성 변경은 이 저장소에서, 브라우저 스타일·상호작용·자산 변경은 프런트엔드 저장소에서 진행합니다.

## Render 등 Node 호스팅

이 사본은 배포 준비용 소스이며 자동으로 배포하지 않습니다. Node 웹 서비스의 빌드 명령은 npm ci && npm run build, 시작 명령은 npm start입니다. 별도 Background Worker는 같은 소스로 npm run worker를 실행합니다. 웹 서비스와 작업자 모두 동일한 DB와 필요한 서버 환경변수를 사용해야 합니다. 실제 마이그레이션은 권한을 분리하여 별도 단계에서 실행합니다.

Dockerfile도 제공하며 db/와 빌드 결과, 로컬 Windows 설정 보조 파일을 실행 이미지에 포함합니다. .env는 이미지에 포함하지 않습니다. compose.editorial.yaml은 실행 구성 예시입니다.

MEDIA_ROOT는 비공개 영구 디스크의 절대경로로 설정합니다. 업로드 파일을 사용하는 웹·작업 프로세스가 해당 경로에 접근할 수 있는 배치를 별도로 구성해야 합니다. 임시 파일 시스템만 사용하면 재배포 때 업로드가 사라질 수 있으므로 DB와 파일을 함께 백업합니다. 이 사본의 파일 저장소는 기존 로컬 파일 시스템 방식이며 R2 같은 외부 객체 저장소 연결은 별도 작업이 필요합니다.

SOURCE_PARSER_PATH 기본값은 backend/source-parser.js입니다. 수집 파서 작업자를 위해 이 파일도 배포합니다. 이메일·AI·공식 보고 연결은 해당 공급자 환경변수를 준비한 경우에만 사용할 수 있습니다.

## 분리본 보안 회귀 테스트

2026-10-12 점검에서 별도 관리자 계정·세션 회수, 로그인 요청 제한, SSE 권한 재확인, URL 수집의 취소·승인 회수, 미디어 교체 원자성, 날짜·댓글 페이지 입력, HTTP 본문 시간·크기·동시 처리 제한을 보강했습니다. 승인된 홈 디자인·애니메이션은 유지하고 관리자 버튼의 저장·확인 동작을 보강했습니다.

    npm run test:redteam
    npm run test:redteam:full

첫 명령은 보안·사용자 동작·인증 호환 회귀를, 두 번째는 기존 콘텐츠·FAQ·애니메이션·업무 기능 회귀까지 실행합니다. 테스트는 Node 24의 타입 변환과 프로젝트 로더를 사용하며 먼저 백엔드를 빌드합니다. 옆에 danwisoft-frontend 저장소가 필요합니다. 다른 위치라면 FRONTEND_ROOT에 프론트 저장소의 절대 경로를 설정하세요. 프론트 자체 검사는 그 저장소에서 npm test로 실행합니다.

runner는 실제 DB 주소·API 키·인증 비밀값을 전달하지 않고 .env를 읽지 않습니다. 합성 계정과 임시 PGlite/로컬 HTTP 서버를 사용합니다. tests/results/ 보고서와 work/ 테스트 자료는 Git에서 제외됩니다. 매체 파서 테스트는 빌드된 별도 작업자에서 실행됩니다. 사용자 화면 테스트는 실제 HTML·스크립트에 대한 JSDOM 이벤트 검사이며, 실제 브라우저 배치·입력을 검사한 것으로 해석하지 않습니다.

본문을 받는 요청은 프로세스당 최대 8개로 제한하고 응답 완료·중단 시 해제합니다. 초과 시 503과 Retry-After: 1을 반환합니다. 일반 GET/HEAD·SSE는 제외하지만 GET에 본문 전송 헤더가 있으면 같은 한도를 적용합니다. 원문 버퍼의 산술 합계는 최대 112MiB이며, 복사본·파싱·DB·응답까지 포함한 총 메모리 한도를 보장하는 수치는 아닙니다. 본문 전송은 30초, 헤더는 10초로 제한합니다. Node 서버 접속 한도도 적용하며 실제 CDN·프록시·플랜 제한은 별도 확인해야 합니다.

운영 DB의 다중 연결 경합, Vercel/Render의 TLS·프록시·배포 설정, 대량 트래픽, 실제 브라우저, S3/R2의 IAM·CORS·업로드는 이번 격리 검수에 포함하지 않았습니다. S3/R2 저장소 기능은 아직 연결하지 않았습니다. 실제 서비스에 연결하기 전 별도 운영 검수가 필요합니다.

문의의 DB 삭제가 완료된 후 첨부 저장소 정리에 실패하면 cleanupPending을 반환합니다. 삭제 대상 저장소 키는 Owner만 볼 수 있는 inquiry.delete 감사 기록에 남기며 다른 권한·SSE에는 제공하지 않습니다. 자동 재시도 작업자는 없으므로 이 표시가 나오면 Owner가 해당 감사 기록을 확인하고 저장소 후속 정리를 진행해야 합니다.
