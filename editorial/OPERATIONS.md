# 단위소프트 인사이트 운영 인계

2026-10-08 기준. 기존 홈 디자인과 애니메이션은 고정하고, 정책 안내 바로 아래에 새 글·기존 글 목록을 연결하고 FAQ 버튼 간격을 수정했습니다. 기존 PostgreSQL 콘텐츠·버전·권한 구조 안에 인사이트를 추가했습니다.

## 지금 연결된 범위와 남은 운영 연결

코드는 직접 작성, DB 자동 저장, 버전 충돌·이력 비교·복원, 버전 지정 미리보기, 검토·승인·예약·취소, 휴지통, 자료 수집, 출처 근거 선택, AI 작성 작업, 댓글·답글·추천·신고, 공개 검색·페이지 이동·RSS·사이트맵까지 연결합니다. 관리자 글 작성은 기존 `/admin` 안에서 진행합니다.

운영 PostgreSQL 서버와 Anthropic 키는 아직 제공되지 않았습니다. 검수는 분리된 PostgreSQL WASM 저장소와 모형 응답으로 진행했습니다. 실제 PostgreSQL의 여러 연결 간 경합, 실제 계정 모델 확인, 유료 작성 호출, 운영 서버 재시작·실제 예약 실행, 사이트 프록시와 캐시 반영은 연결 후 검수해야 합니다. 네이버 검색·웹 검색·Threads·Instagram은 미연결입니다. 실제로 동작한다고 표시하지 않으며 URL HTML·RSS 기능과 분리합니다.

요청 문서에 따라 운영 데이터 초기화, 실서비스 자동 배포, 대량 외부 호출은 수행하지 않았습니다. 화면 캡처의 “검수용 글”은 로컬 검수 저장소에만 있으며 운영 사이트에 올릴 초기 글이 아닙니다. 기본 등록은 공개되지 않은 주제 후보 12개입니다.

## 환경과 실행 순서

Node.js 24.15 이상을 사용하세요. 이번 검수는 24.19.0에서 수행했습니다. `.env.example`의 빈 값을 운영 비밀 저장소에서 준비합니다. `.env`를 저장소·브라우저·문서에 공개하지 마세요.

- `DATABASE_URL`: 운영 PostgreSQL 연결 주소. 제공 환경의 CA와 TLS 검증을 유지합니다.
- `GATEWAY_SECRET`: Sites 프록시와 Node 서버가 공유하는 요청 서명 비밀값.
- `OWNER_EMAIL`: 기존 관리자 최초 Owner를 확인할 실제 로그인 이메일.
- `SITE_URL`: 실제 사이트 주소. Origin·canonical·쿠키 기준으로 사용합니다.
- `PRIVATE_SITE`: 현재 비공개 사이트의 접근 범위를 유지합니다. 공개 전환은 별도 운영 결정입니다.
- `VISITOR_COOKIE_SECRET`: 서버에서 생성한 최소 32자 난수. 익명 추천 쿠키를 서명합니다. 재시작해도 유지해야 기존 방문자 추천 상태가 이어집니다.
- `ANTHROPIC_API_KEY`: 선택 기능. 서버에만 보관하며 키가 없어도 수동 작성·승인은 가능합니다.
- `SOURCE_PARSER_PATH`: 기본 `backend/source-parser.js`. 프로젝트 디렉터리에서 실행하고 Docker 작업 디렉터리는 `/app`입니다.

운영 연결 후, 먼저 백업과 별도 복원 DB를 확보합니다. 기존 스키마를 지우지 않고 `npm run migrate`, `npm run seed`를 명시적으로 실행합니다. 마이그레이션은 001 → 002 → 003 순서로 한 트랜잭션과 DB 잠금에서 적용하며 이미 적용된 버전은 건너뜁니다. seed는 없는 기본 항목만 추가합니다.

웹 서버는 `node backend/index.js`, 별도 작업 프로세스는 `node backend/editorial-worker.js`로 실행합니다. 웹 요청 안에서 작성 작업을 오래 실행하지 않습니다. worker의 종료 유예는 80초 이상을 권장합니다. `compose.editorial.yaml`은 실행 예시이며 이 작업에서 컨테이너를 배포하지 않았습니다. 예시 웹 포트는 로컬로만 노출되므로 실제 HTTPS 프록시와 Sites의 `BACKEND_URL` 연결이 필요합니다. 직접 Node 주소로 우회 접속한 요청은 서명 없이는 거절됩니다.

`DEV_DATABASE`, `DEV_USER_ID`, `DEV_USER_EMAIL`, `DEV_DATA_PATH`는 localhost 검수 전용입니다. 운영에 설정하지 마세요. 검수 스크립트 `seed-insights-qa.ts`는 개발 플래그를 검사하며 운영 seed에 포함되지 않습니다.

## 최초 가동

초기 상태는 `paused:true`, `enabled:false`, `MANUAL`, 수집·AI·예약 OFF입니다. 중지 상태에서도 수동 저장·수정은 가능합니다. 공개 발행과 작업 실행은 운영 중지를 해제한 뒤 진행합니다.

1. 실제 Owner 로그인으로 직접 글 한 건을 저장합니다. 새로고침·두 창의 버전 충돌·미리보기 접근 권한을 확인합니다.
2. 사실·개인정보·실제 경험을 확인하고 정확한 초안 버전을 승인합니다. worker를 켜 수동 공개 한 건의 HTML·목록·홈·RSS·사이트맵을 확인합니다.
3. 수집 기능을 쓰려면 정확한 출처 호스트와 이용 조건을 운영자가 허용합니다. URL 1개부터 등록·수집하고 본문 확보 여부, 원출처·최종 URL·저자·시각·해시를 확인합니다. RSS는 기사 발견 경로이며 기사 본문 확보로 표시하지 않습니다.
4. 본문 안의 필요한 짧은 구간을 직접 선택하고 주장·적용 조건·불확실성을 작성해 검증된 근거로 저장합니다. 주제에는 해당 출처를 연결합니다.
5. AI를 사용한다면 모델 확인과 예산 설정을 마친 뒤 승인한 작은 호출 한 건만 시험합니다. 실제 usage와 추정 비용·미확정 예약금이 장부에 남는지 확인한 다음 자동 초안 모드를 검토합니다.
6. 예약은 한국 시간으로 지정합니다. 동일 예약 재요청은 같은 작업 ID를 반환합니다. 글을 수정하거나 승인을 취소하면 예약이 해제됩니다. 주간 슬롯은 최대 3개, 자동 초안은 하루 최대 2개입니다. 승인된 글이 없거나 한 시간 이상 지난 슬롯은 건너뛰고 이유를 기록합니다.

## 직접 글과 AI 제안

글은 문단·소제목·목록·인용·표·코드·이미지 블록으로 편집합니다. HTML과 가져온 코드 예시는 실행하지 않습니다. 공개 이미지와 대체 텍스트를 확인합니다. 관리자에 표시되는 실제 공개 서비스·사례 이름으로 관련 항목을 선택합니다.

자동 저장은 DB 초안 버전을 갱신합니다. 저장 중·실패·다른 창의 충돌을 구분하며, 충돌 시 현재 입력을 유지한 채 최신 저장본과 비교합니다. 이력 복원은 새 초안을 만들고 기존 이력을 덮어쓰지 않습니다. 공개본 수정 중 방문자에게는 이전 승인 공개본을 유지합니다.

AI 생성은 초안 → 사실 검수 → 문체 편집 → 최종 검수로 분리합니다. 최종 검수에는 문체 편집 전후 글이 전달됩니다. `editorial/WRITING_PROFILE.md`와 `src/editorial-profile.json`이 실제 작성 지침입니다. `src/editorial-ai.ts`에 각 단계 시스템 프롬프트가 있습니다. 장문의 숨은 사고 과정을 저장하거나 공개하지 않습니다.

제목 제안은 제목·요약만, 문단 재작성은 선택한 한 문단만 적용합니다. 나머지 블록은 보존합니다. 제안 이후 글 버전이 바뀌면 덮어쓰지 않습니다. 같은 작성 작업의 적용은 한 번만 이루어지며 같은 요청 재전송은 적용한 글 ID를 반환합니다. 적용은 초안 저장일 뿐 공개 승인이 아닙니다.

## AI 모델·비용 확인

현재 계정에 제공되는 정확한 모델 ID를 입력하고 모델 확인을 실행합니다. 실제 API가 알려주는 구조화 출력 지원과 입력·출력 한도를 사용합니다. 연결하지 않은 모델·과거 가격을 고정 기본값으로 넣지 않았습니다.

운영자가 공식 요금 URL·확인일·USD 입력 및 출력 단가를 입력하고 확인합니다. 글 운영 일일/월간 한도, FAQ를 포함한 전체 월간 상한과 호출 수 한도를 따로 정합니다. 수집 및 외부 자료 처리 승인도 필요합니다. FAQ의 선택적 유료 안내 역시 같은 전체 장부·상한을 사용합니다.

호출 전 예약과 호출 후 usage 정산을 구분합니다. 모델·출력 한도·가격은 예약 시점의 같은 설정을 사용합니다. 서버가 응답했으나 형식이 잘못되거나 거절한 호출도 측정 usage를 기록합니다. 네트워크 오류로 사용량을 알 수 없으면 `UNKNOWN` 예약금을 유지하며 0원으로 복구하지 않습니다. 화면 금액은 추정이며 실제 공급자 청구서가 아닙니다. 미확정 건은 공급자 사용 내역과 대조해야 합니다.

각 작업은 ID·단계·시도 횟수·usage ID·오류 코드로 확인합니다. 키나 원문 SDK 오류를 로그에 남기지 않습니다. 재시도는 같은 작업에 최대 3회이고 내부 SDK 자동 재시도는 껐습니다. 실행 권한이 만료되거나 취소된 worker는 새 유료 호출과 결과 적용을 하지 못하도록 검사합니다.

## 출처 보관·실패 처리

URL 수집은 별도 Node 코드 한 곳에서 처리합니다. 승인 호스트·공개 IP·모든 DNS 응답·고정 연결 주소·실제 소켓 주소를 확인합니다. 리다이렉트도 다시 검사하고 로그인·접근 차단·CAPTCHA를 우회하지 않습니다. 프록시 환경변수를 사용하지 않습니다. 요청·압축 해제·파싱 시간과 크기, 실행 동시 수를 제한합니다.

DOM 스크립트 실행과 리소스 로딩은 꺼져 있고 XML 엔티티는 거절합니다. 본문 확보, 기사 발견만, 접근 차단, 빈 본문, 동적 본문 미확보, 호출 제한을 나눕니다. 원문 HTML 전체를 장기 보관하지 않고 제한된 추출 구간·해시·짧은 근거를 보관합니다. worker는 기능이 꺼져 있어도 만료 구간을 지웁니다. 만료 뒤 같은 원문을 재수집할 때는 조건부 헤더 없이 본문을 다시 확보합니다.

출처 본문 해시가 바뀌면 관련 근거는 재검토 상태가 되고 해당 초안의 승인·미실행 예약이 해제됩니다. 사실 자료 속 지시문은 시스템 지침이나 작업 승인으로 쓰지 않습니다. 승인한 공개 사례만 작성 입력에 투영하며 문의 자료·비밀번호·API 키·원본 내부 DTO를 전달하지 않습니다.

## 발행 저장과 반영 확인

작업 화면은 DB 공개 커밋과 렌더링 확인을 따로 표시합니다. `db_committed_at`이 있으면 글은 DB 공개 상태이며, 반영 실패를 이유로 글을 다시 만들거나 중복 발행하지 마세요. 같은 작업의 반영 확인만 재시도합니다. 글 버전·승인·운영자 권한이 바뀐 작업은 다시 승인해야 합니다.

현재 `serving_ready`는 서버의 공개 DTO로 SSR 렌더링 검사를 통과했다는 의미입니다. 운영 사이트를 외부에서 직접 열어 확인했다는 의미가 아닙니다. 실제 배포 후에는 Sites 프록시, 공개 HTML, CSS·스크립트, 홈·목록·태그·관련 글·RSS·사이트맵을 직접 확인해야 합니다. HTML은 요청마다 DB에서 제공되며 공개 삭제·숨김이 오래된 정적 글로 남도록 게시물을 고정 빌드하지 않습니다.

## 댓글·추천·태그

댓글은 운영자 검토 후 공개됩니다. 수정하면 다시 검토하고, 삭제된 부모에 공개 답글이 있으면 삭제 안내를 남깁니다. 답글은 한 단계만 지원합니다. 공식 답글은 서버의 Owner 권한으로 구분합니다. 비밀번호는 PBKDF2 해시만 보관하고 공개 DTO에 포함하지 않습니다. 댓글 URL에는 `ugc nofollow`를 적용합니다.

추천은 서버가 서명한 익명 방문자 쿠키와 DB 고유 키로 중복을 막습니다. 글별 댓글·추천을 끌 수 있습니다. 태그 병합은 공개 이력을 바꾸지 않고 현재 초안 관계를 새 버전으로 정리하며 이전 URL을 영구 이동시킵니다. 여러 번 병합한 관계도 최종 태그에 연결됩니다.

## 백업·복원

기존 백업은 콘텐츠 외에도 버전·승인·예약/생성 큐·출처/근거·댓글/신고/추천·비용 장부·설정·캐시 epoch를 포함해야 합니다. DB 파일이나 비밀 환경변수를 브라우저와 공개 산출물에 넣지 마세요. 이 작업에서 실제 운영 백업·복원은 수행하지 않았습니다.

운영자가 별도 백업 저장소에 `pg_dump --format=custom --file=<승인된_백업파일> --dbname=<보호된_연결환경>`로 백업합니다. 비밀 연결 문자열을 명령 기록에 직접 적지 말고 해당 환경의 비밀 주입 방식이나 서비스 파일을 사용합니다. `pg_restore --dbname=<별도_복원_DB> <백업파일>`로 먼저 복원 시험을 하며 운영 DB를 지우는 `--clean`이나 초기화 절차를 자동 수행하지 않습니다.

복원 DB에는 worker를 먼저 켜지 마세요. `editorial_config`를 `paused:true`, `enabled:false`, 수집·AI·예약 OFF로 설정한 후 버전/승인/댓글/비용 수를 원본과 비교합니다. 만료 리스·지난 예약·이미 커밋된 발행·미확정 비용과 출처 만료를 검토합니다. 운영 전환은 연결 정보 제공과 별도 운영 승인 뒤 수행합니다.

## 검수 명령과 자료

`npm run check`, `npm run build`, `npm run test:insights`, `npm run test:editorial`, `npm test`를 사용합니다. 검수 저장소는 운영 PostgreSQL과 분리합니다. 상세 결과·캡처는 한 단계 위 `../insights-qa/검수-보고서.md`에 정리합니다. 실제 API 가동 확인을 모형 테스트 결과로 대신하지 않습니다.
